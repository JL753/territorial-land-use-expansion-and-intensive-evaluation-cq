# 数据更新与 AI 助手配置

## 1. 数据时效性原则

本系统区分三类数据：

- **可高频更新的地理要素**：OpenStreetMap 建筑、道路、POI。建议以周或月为周期获取快照，不将公共 Overpass 实例当作高并发生产下载服务。
- **按年度或产品版本发布的数据**：CLCD 土地覆盖、GHSL 建成区、DEM。系统可在线检查版本，但产品本身不是实时流。
- **滞后发布的统计资料**：人口、GDP、产业增加值等。需等待官方统计年鉴或统计公报发布，采集后记录价格口径、统计口径和来源页。

CLCD 当前公开记录覆盖 1985—2025 产品期，实际可用年份以 Zenodo 文件清单为准。它是 Landsat 年度土地覆盖产品，不代表每天或每月都能得到新的建设用地观测。来源：https://zenodo.org/records/18180184

## 2. 在线版本检查

页面：`/data-center.html`

API：
- `GET /api/v1/data-sources/`：读取数据源目录和最近检查历史。
- `POST /api/v1/data-updates/check/`：检查指定数据源；当前 CLCD 支持在线 Zenodo 元数据检查。
- `POST /api/v1/assistant/`：提交问题和当前页面上下文。

命令行检查：

    python manage.py check_data_updates --source clcd

建议部署服务器每日或每周定时运行。该命令只检查版本元数据并写入 `DataUpdateRun`，不会自动下载 800MB 级栅格，也不会改写正式研究数据。

## 3. 正式数据更新流程

1. 检查数据源是否发布新版本。
2. 下载原始数据到独立暂存目录。
3. 保存数据源 URL、版本、发布日期、许可、文件大小和校验值。
4. 进行坐标系、空间覆盖、区县匹配、NoData、分类编码和完整性检查。
5. 运行年度区县统计和变化分析。
6. 生成候选数据版本及差异报告。
7. 研究者确认后发布；旧版本继续保留以保证论文实验可复现。

不要将新年度土地覆盖分类数据直接并入旧版社会经济统计并自动计算集约利用得分。社会经济指标必须满足同年、同口径和质量等级要求。

## 4. AI 悬浮助手

助手通过 Django 页面中间层注入到首页、移动端、桌面端、三维页、区县三维页、数据中心和毕设工作台。

默认模式：
- 读取当前已入库的区县年度数据。
- 解析问题中的年份、区县和指标。
- 返回数值及证据行。
- 当用户请求尚未入库的年份时，明确报告缺失，不用其他年份代替。

可选 Ollama 模式：

    ollama serve
    ollama pull qwen3:8b
    export CQ_OLLAMA_MODEL=qwen3:8b
    export CQ_OLLAMA_BASE_URL=http://127.0.0.1:11434
    python manage.py runserver

模型只能基于服务端提供的研究证据回答。没有配置模型时，助手仍可进行数据检索，但不会把规则检索冒充大模型回答。

## 5. 区县三维地图

页面：`/district.html?code=500105`

21 个研究区县由同一套独立场景模板加载，支持区县选择、地形开关、地形晕渲、边界开关和已入库年度指标切换。DEM 瓦片用于真实地形起伏；区县指标拉伸属于专题表达，不是建筑物高度。建筑级三维需要额外的建筑轮廓和可靠高度数据，并应单独标记高度来源。

MapLibre GL JS 的 raster-dem / setTerrain 用于三维地形渲染，详见：https://maplibre.org/maplibre-gl-js/docs/examples/3d-terrain/

## 6. 当前限制

- CLCD 在线检查已实现；批量下载、裁剪和年度区县统计仍需按服务器存储、带宽和任务时长安排，不能在网页请求中同步下载大文件。
- GHSL、Copernicus DEM、OSM 和官方统计数据目前进入来源目录；未提供无需凭据的稳定版本 API 的来源标记为人工核验。
- 地形瓦片依赖第三方公共服务和网络可达性；生产部署应考虑本地缓存或自建瓦片服务，并遵守来源许可与署名要求。
- AI 大模型需要用户自行配置并运行 Ollama；不配置模型时仍提供证据型数据检索。
